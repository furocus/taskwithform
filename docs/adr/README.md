## 作成とレビュー

- [共有skill](../../.agents/skills/adr-draft-from-code/SKILL.md)と[テンプレート](../../.agents/skills/adr-draft-from-code/assets/adr-template.md)を使う。番号は3桁の連番、ファイル名は`NNN-short-decision.md`。同時作業で番号が重なったら取り込み前に調整する。
- 区分は「現状から復元」「新規提案」。構成・API契約・データモデル・責務境界などの重要な判断を対象とし、小さな修正すべてに要求しない。
- 状態は「草案／未レビュー」「合意済み」「廃止」「置換済み」。人が根拠と理由を確認して状態を更新する。提案を実装・合意済みとは扱わず、検証の実施状況は別に記す。
- 過去の理由や比較履歴は推測せず、未確認事項として担当者に確認する。草案作成だけではアプリ実装や外部操作を許可したことにならない。
- 置換時は旧記録を消さず、旧・新両方に関係を記載し、索引も更新する。

初期草案ではソースとテスト定義を確認したが、アプリのテスト・実Googleアカウントでの動作検証は今回未実施。
