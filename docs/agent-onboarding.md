# Codexの共通手順と個人設定

共有ルールはルートの[AGENTS.md](../AGENTS.md)、個人の担当範囲とログ保存先はGit対象外の`AGENTS.local.md`へ置く。担当制限はエージェントへの指示であり、ファイルへの書き込みを権限で阻止する仕組みではない。

## 初回・既存設定の移行

1. **この変更を取り込む前に**、既存の`AGENTS.local.md`をリポジトリ外の安全な場所へコピーする。これまでは追跡されていたため、追跡解除の変更を取り込むと手元のファイルも削除される場合がある。
2. ブランチの変更を取り込んだ後、退避した内容を`AGENTS.local.md`へ戻す。初めて作る場合は[雛形](../AGENTS.local.example.md)をコピーする。他人の担当や保存先は使わない。
3. 下のプロンプトを各自のCodexへ渡し、担当・編集範囲・作業ログ保存先を設定する。範囲は担当者の合意や今回のIssueで明示されたパスにする。
4. VS CodeはRemote WSLかDev Containersでリポジトリを開く。ターミナル利用時も、CodexとGitが参照するリポジトリを確認する。
5. Codexに読み込んだ指示、担当範囲、共有skills、ログ保存先を説明させる。共有skillsが見つからない場合はファイルの存在を確認し、セッションを開始し直す。

担当範囲の例は、バックエンドなら`backend/**`、DBなら`src/database/**`、UIなら`src/app/**`・`src/pages/**`・`src/styles/**`・各`components/`。同期処理・API境界・共通設定などは担当を推測せず、個別に合意したパスを追加する。これらは例であり、他領域への編集許可ではない。

### 各自へ渡す初期設定プロンプト

```text
既存のAGENTS.local.mdを最初に読み、AGENTS.mdとAGENTS.local.example.mdを確認してください。
既存記述を保ち、雛形の4項目を設定してください。同名項目があれば追記せず更新してください。

私の担当：［記入］
合意した編集範囲：［リポジトリ相対パスを記入］
作業ログ：［Obsidian内のMarkdownファイルへの絶対パスを記入］

追加する設定は見出し1つと「担当・編集範囲・担当外・作業ログ」の4項目だけにしてください。
担当外の扱いは雛形の文言を使い、共有ルール・skillsの説明・今回の確認結果は個人設定へ複写しないでください。
不明な値は「未設定」とし、判明済みの項目を先に保存して、不足する値だけを最後に質問してください。
担当範囲や保存先は推測しないでください。
実際のログパスが示されている場合だけ読み取り可否を確認し、未作成なら親フォルダの存在を確認してください。
この初期設定ではログやフォルダを作成せず、編集するファイルはAGENTS.local.mdだけにしてください。
AGENTS.local.mdがGit対象外であることを確認し、追跡中なら報告してください。
最後に担当範囲・担当外の扱い・参照する共有skills・ログ保存先と未確認事項を短く説明してください。
```

保存先はCodexの実行環境ごとに違う。Windowsの`C:/...`、WSLの`/mnt/c/...`、コンテナ内のパスを無条件に読み替えない。参照できない場合はログをチャットで受け取り、利用可能な保存先を確認する。Dockerのマウント変更を自動で行わない。

## 共有skills

| skill                                                                 | 使用する場面                                                               |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| [adr-draft-from-code](../.agents/skills/adr-draft-from-code/SKILL.md) | 既存設計を復元するとき、または重要な新規設計の草案を作るとき               |
| [luna-code-writer](../.agents/skills/luna-code-writer/SKILL.md)       | コード・テストを実装するとき。Lunaが使えなければ親が理由を報告して続行する |
| [worklog-summary](../.agents/skills/worklog-summary/SKILL.md)         | 実作業の終了時や、要約・引き継ぎを依頼したとき                             |

通常のフォルダとして`.agents/skills/`へ同梱するため、コピー・リンク設定・専用インストーラーは不要。ログは「作業・結果と判断・確認・次」の短い4項目で、既存内容を保って記録する。保存先未設定時は要約の提示と保存先確認にとどめる。

新規skillは既定でGit対象外。個人用ならそのまま使い、共有すると決めたものだけ`.gitignore`の許可対象へ追加し、付属ファイルも含めてレビューする。既存の共有skillを個人都合でGit対象外へ変更しない。`git add -f`でこの区分を迂回しない。

個人用と共有版で同名のskillがある場合、このリポジトリではAGENTSに記載された共有版のパスを使う。個人用を削除する必要はない。grilling・github-cliは個人用のままで、全員への導入は必須にしない。

## ADRと毎回の作業

作業前に担当領域の[ADR索引](adr/README.md)を読み、重要な構成・API契約・データモデル・責務境界を変更する場合は草案を起こす。小さな修正すべてにADRは不要。草案は実装許可やチームの合意を意味せず、確認後に合意状態へ進める。

調査・計画・文書編集だけの作業はLunaへの実装委譲を必要としない。テストの存在と今回実行した結果を区別し、未実施なら明記する。ログを埋めるためのテスト・外部通信・Docker操作は行わない。
